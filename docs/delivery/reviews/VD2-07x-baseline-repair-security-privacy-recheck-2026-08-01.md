## Conditions carried into implementation acceptance

1. The implementer must preserve the existing `Any` query and every no-control/disclosure assertion while adding the four `StaticText` checks; a query replacement or copy change is outside this acceptance.
2. The custom AI accessibility label must first be shown to make the new role test RED, then only that override may be removed for the green run. No fixture/demo state or test-only control may be introduced.
3. Delivery must execute the scratch-index commands only against the temporary index, select no full untracked file and no protected-export/root hunk, and record an unreleasable result rather than broad-stage if separation fails. A scratch index is never build evidence.
4. Before accepting implementation, independently inspect the isolated diff and retained evidence for the original safe-payload contract: dynamic success data remains only the display filename; no key, path, document metadata, URL, review, or operation token appears in Settings, the root presentation, fixtures, logs, screenshots, or reports.

No ADR is required for this bounded accessibility/test and fixture-date repair. This review accepts planning only; the fresh implementer, independent QA/code review, and subsequent architecture/security/TPM/delivery gates remain required before Task 2 can begin.
