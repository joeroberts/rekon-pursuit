## Scope and method

## Validation rubric

- [x] An opaque, model-owned operation token is invalidated on every new review, cancellation, terminal failure, and workspace transition.
- [x] Success publication requires both a current captured token and the existing identical-store guard.
- [x] The confirm-to-cancel race has a deterministic, gated test that must be green in both signed matrices.
- [x] The success event and root/dialog boundary carry only the display filename as dynamic export data.
- [x] Fixture/demo, sensitive-data, document, no-network, and signing/entitlement constraints remain explicit and testable.
