## Non-negotiable visual rules

- Treat the package as one visual system: dark app shell, restrained cyan and
  violet accents, compact hierarchy, consistent sidebar/navigation, and quiet
  surface borders.
- App-owned forms use labels above the control and exactly one native control
  surface. Do not place native fields inside a second bordered shell.
- Idle fields are quiet: deep-navy fill, thin neutral/navy border, compact
  height and padding. Cyan is reserved for real focus/active selection.
- Use concise section dividers and spacing. Do not create tall repetitive boxed
  rows or a scrolling wall of inflated fields.
- Opportunity forms retain wide responsive logical columns and compact stacked
  groups. Contacts remains a concise detail-panel editor.
- Settings dialogs follow the supplied protected-export/recovery compositions.
- Do not start VD2-07c layouts before VD2-07b merges, but VD2-07b must not
  establish a visual language that conflicts with the Activity/AI references.
- Preserve existing behavior, labels, bindings, accessibility semantics,
  persistence, recovery ownership, and native file-panel boundaries.

## Delivery rule

Do not substitute test green status for visual fidelity. Before accepting a
slice, compare its actual rendered screen to every relevant reference in this
package. New functionality tests are not required for a presentation-only
change; use existing regressions after visual implementation to confirm no
behavior was disturbed.
